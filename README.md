# CEC-AD: Claim–Evidence Consistency Benchmark for Agent Deliverables

This dataset accompanies the paper *Claim–Evidence Consistency for Agent Deliverables: A Benchmark and Measurement Framework* (NeurIPS Evaluations & Datasets submission). It measures whether each result claim in an LLM agent's natural-language report is supported by the execution record of the same run.

## What is released

- `data/claims_corpus.jsonl` — 6,366 claims extracted from 89 captured agent sessions across three domains (file/code, data analysis, writing/retrieval). Each line has `id`, `claim`, `evidence` (compressed view), `domain`, `state` (default-engine state), `source`, `session_id`.
- `data/gold_359.json` — the 359-claim gold standard: votes from three annotators, majority/adjudicated label, and label source.
- `data/items_359_gold.json` — evaluation items used in the paper (claim + evidence + human label).
- `data/split_dev_test.json` — session-clustered dev/test split (180/179).
- `data/annotations/` — original annotation workbooks (A/B/C, pilot and formal).
- `data/release_variant_numbers.md` — numbers computed on this de-identified release (see note below).
- `croissant.json` — machine-readable Croissant metadata.

## Intended use

Research on claim–evidence consistency, deterministic rule judges versus LLM judges, and evaluation methodology for agent deliverables. Reuse requires citing the paper.

**Not intended for**: estimating deployment accuracy from the 359-claim stratified sample; claiming contradiction-detection capability (contradictions are rare and annotation-unstable in this corpus); cross-language or cross-domain transfer without re-validation.

## De-identification and number caveat

The release is **strongly de-identified**: absolute paths → `<PATH>`, usernames/personal dirs → `<USER>/<HOME>`, phone-like strings → `<PHONE>`, emails → `<EMAIL>`, internal project directory names → `<REPO>`, GitHub account names → `<ACCOUNT>`. Claims and evidence are otherwise verbatim from real traces.

Because paths/URLs are checkable evidence spans, masking changes a few judge decisions. On the 179-item test split (apply `run_all.py` from the code package):

| Judge | This release | Paper (internal text) |
|---|---|---|
| Minimal-capture rule judge | 30.2% | 31.8% |
| Heuristic | 28.5% | 29.6% |
| Rule v2 | **63.1%** | **63.1%** |
| Constant-P prior | 45.3% | 45.3% |

The main claim — rule v2 at 63.1% versus 28–32% for the rule judge and heuristic — is unchanged.

## Annotation protocol

Three independent annotators labeled the claims under a 12-chapter manual: five states (S supported, P partially supported, N no evidence, C contradicted, L not scored), decision order L → N → C → S → P (conflict dominates partial matches), and a relevance gate for tool errors. Human–human agreement is Fleiss' κ = 0.628. See `annotations/` and the paper's Appendix A.

## Hosting on GitHub

This repository is self-contained: `data/` (benchmark files), `code/` (reference implementation and reproduction scripts), `croissant.json` (machine-readable metadata), and `README.md` (dataset card). Total size is about 9 MB, so no Git LFS is needed.

**Reproduce the main table** (after cloning):

```bash
cd code && python -m pip install -r ../requirements.txt
python repro/run_all.py --data ../data
```

**Croissant**: `croissant.json` follows Croissant 1.1 (including RAI fields). `contentUrl` values use the `https://raw.githubusercontent.com/<GITHUB_USER>/cec-ad/main/` prefix; replace `<GITHUB_USER>` after creating the repository (or run `实验/P2_20261108/prepare_github_kit.py` again with the environment variable `GITHUB_USER` set).

**Double-blind review**: do not link a repository that reveals author identity. During review use the anonymous snapshot generated by `anonymous.4open.science` from this repository (see `docs/upload_github.md`).
